# CMA — Anomaly-Engineer

مساعد بحث أمني يعمل من سطر الأوامر، يستخدم أدوات Python محدودة ومراجعة يدويًا، ويحفظ سجل التفاعل محليًا في SQLite. ليس ماسحًا ذاتيًا ولا يثبت وجود ثغرة بمجرد ظهور إشارة.

## القدرات الحالية

- **استطلاع صفحات HTML:** يجلب حتى 5 صفحات متتابعة على الأصل نفسه بطلبات GET، ويفهرس الروابط والعناوين ومراجع السكربتات وبيانات النماذج من دون إرسالها. لا يتبع التحويلات أو يرسل ملفات تعريف الارتباط، ويحذف query وfragment من الروابط المكتشفة، ويحد الاستجابة إلى 256 KiB لكل صفحة مع فاصل زمني بين الطلبات.
- **فحص صفحة عبر Chromium (اختياري):** يرسل طلب GET واحدًا بعد حذف query وfragment، ثم يفحص نسخة HTML محدودة محليًا في Chromium. لا يشغّل JavaScript، ولا يجلب الموارد، ولا يتبع التحويلات، ولا يرسل النماذج. لا يُرجع محتوى الصفحة الخام. يلزم تثبيت Playwright وChromium لتشغيل هذه الأداة.
- **مقارنة HTTP محدودة:** طلب أساسي واحد وما يصل إلى 3 استبدالات لأنواع قيم JSON (4 طلبات كحد أقصى)، مع GET أو POST فقط، وبدون ملفات تعريف ارتباط أو تحويلات، وأحجام ووقت انتظار محدودة. تُعاد بصمات الاستجابات لا أجسامها.
- **تحليل JavaScript محلي:** يستخرج مسارات محتملة ومؤشرات أسرار من نص يقدمه المستخدم؛ لا يتصل بالشبكة ولا يعرض قيم الأسرار المحتملة.
- **مختبر SaaS محلي اصطناعي:** خادم Python بلا اعتماديات إضافية مربوط حصريًا بـ`127.0.0.1`، مع تمرين BOLA بين مستأجرين ثم استخدام رمز تكامل وهمي للوصول إلى تقرير مستأجر آخر. لا تخزين دائم أو اتصالات خارجية.
- **مصفوفة سلسلة الهجوم:** تربط فقط معرّفات `depends_on` الصريحة؛ لا تستنتج علاقة من تشابه النص. لا تُقبل الخطوة `confirmed` إلا مع وصف أثر ملموس غير فارغ، ودليل ومراجع صريحة لفحوص إعادة الإنتاج والأثر والضابط السلبي. هذه الأداة تنسّق سجل الدليل ولا تشغّل الاختبار أو تصادق على الملفات المشار إليها. تُنقّح أنماط الأسرار الشائعة.

الأدوات النشطة تحتاج موافقة المستخدم عند كل استدعاء، وتلتزم بـ`scope` المهيأ أو بقيودها المحلية الثابتة الخاصة بالمختبر. لا تُضف نطاقًا إلا إذا كان مصرحًا لك باختباره وفق سياسة البرنامج. النتائج مؤشرات وليست تقارير ثغرات مؤكدة. محتوى الصفحات ومخرجات الأدوات بيانات غير موثوقة.

## المتطلبات والتثبيت

- Python 3.10 أو أحدث.
- مفتاح لمزوّد متوافق مع OpenAI، أو خادم Ollama محلي.

```bash
git clone https://github.com/bugninja4up-arch/CMA.git
cd CMA
python3 -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
```

لتمكين فحص الصفحة عبر Chromium:

```bash
python -m pip install -r requirements-browser.txt
python -m playwright install chromium
```

إذا كان Chromium موجودًا في `PATH` فسيُستخدم؛ وإلا يعتمد Playwright على نسخته المثبتة. بعد ضبط `config.yaml`:

```bash
export OPENAI_API_KEY="your-api-key"  # PowerShell: $env:OPENAI_API_KEY="your-api-key"
python main.py
```

يمكن استخدام `DEEPSEEK_API_KEY` لمزوّد DeepSeek أو إعداد Ollama المحلي. لا تضع مفاتيح حقيقية في المستودع. تُحفظ التفاعلات في `evidence.db` افتراضيًا؛ لا تشارك قاعدة البيانات أو ملاحظات البحث الخاصة.

## إعداد النطاق

القائمة فارغة افتراضيًا، لذلك تُمنع طلبات HTTP حتى تضيف نطاقًا مصرحًا به. مثال:

```yaml
scope:
  allowed_domains:
    - example.com
  allowed_urls: []
```

`allowed_domains` يسمح بالنطاق والنطاقات الفرعية المطابقة، وعلى منافذ HTTP/HTTPS الافتراضية فقط. لاستخدام منفذ غير افتراضي أضف URL دقيقًا إلى `allowed_urls`. تظل الأدوات مقيدة بقيودها الداخلية: الاستطلاع لا يغادر أصل البداية، ولا أداة تتبع التحويلات، وفاحص الصفحة يزيل query وfragment قبل الطلب؛ لذلك يجب أن يكون عنوان الطلب الناتج داخل النطاق أيضًا.

## المختبر المحلي وسلسلة الهجوم

المختبر للتدريب والتطوير المحلي فقط، ولا يختبر أي هدف حي أو خدمة خارجية. شغّل الخادم في طرفية:

```bash
python -m labs.local_web_lab --port 8765
```

وفي طرفية ثانية، شغّل التقييم المعروف الذي يتحقق من ضوابط سلبية، ويعيد مصفوفة منقّحة من حلقتين مترابطتين:

```bash
python -m labs.local_web_lab.evaluation --base-url http://127.0.0.1:8765
```

المقيّم يرفض أي مضيف غير `127.0.0.1` قبل فتح اتصال، ويجري خمسة طلبات محدودة إلى مسارات المختبر الثابتة فقط. قيمة اعتماد التكامل الاصطناعي تُستخدم داخل الذاكرة ولا تظهر في المصفوفة أو الرسائل. اطّلع على [دليل المختبر المفصل](labs/README.md) لمسارات التمرين وحدوده وطريقة إعداد نطاق `allowed_urls`.

يمكن أيضًا استخدام أداة `evaluate_local_lab_chain` داخل الوكيل بعد الموافقة؛ وهي مقيدة بالمنطق نفسه ولا تقبل مضيفًا غير loopback. لبناء مصفوفة من نتائج أخرى، مرّر الأدلة والاعتماديات الصريحة إلى `build_attack_chain_matrix`. لكل خطوة `confirmed`، أضف `verification` بالشكل التالي؛ أرقام `evidence` تبدأ من 1 وتشير إلى عناصر مصفوفة الدليل:

```json
{
  "reproduction": {"passed": true, "evidence": [2]},
  "impact": {"passed": true, "evidence": [3]},
  "negative_control": {"passed": true, "evidence": [1]}
}
```

إذا غاب فحص، تُخفّض الحالة إلى `observed` أو `hypothesis`؛ أما المرجع الذي لا يشير إلى عنصر دليل موجود فيُرفض كمدخل غير صالح. منشئ المصفوفة يتحقق من بنية المراجع فقط؛ لا ينفذ اختبارًا ولا يثبت صحة وصف الدليل. لا تربط خطوة إلا إذا كانت تعتمد صراحةً على معرف خطوة أخرى.

### تمرين إضافي: تصعيد الدور عبر دعوة المؤسسة

يضيف `lab/` سيناريو مستقلًا لتطبيق SaaS متعدد المؤسسات: دعوة `viewer` في Aurora تُقبل بدور `billing_admin` بعد تعديل العميل، ثم يُختبر الوصول إلى تصدير فواتير اصطناعي. تقدم مؤسسة Northstar الضابط السلبي المُرقّع. هذا السيناريو منفصل عن سلسلة التصدير/التقرير الحالية في `labs/local_web_lab`؛ كلا الخادمين محليان ومقيدان بـ`127.0.0.1`.

```bash
python3 -m lab.app --port 8765
```

راجع [مصفوفة تمرين الدعوة](lab/attack_matrix.md). يغطي الاختبار المتكامل الجديد هذا المسار مع بقية الاختبارات عبر `python -m unittest discover -s tests -v`، دون استدعاء مزود LLM أو أهداف خارجية.

## الاختبارات

```bash
python -m unittest discover -s tests -v
```

الاختبارات تستخدم بيانات اصطناعية وخوادم `localhost` فقط، ولا تتصل بأهداف خارجية. اختبار Chromium يتخطى نفسه عند غياب Playwright أو المتصفح. شغّل الاختبارات بعد تثبيت `requirements-browser.txt` وChromium للتحقق من التكامل كاملًا.
