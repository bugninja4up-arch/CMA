# مختبر CMA المحلي: سلسلة تصدير وتقارير متعددة المستأجرين

## الهدف

هذا مختبر تجريبي يملكه المستخدم ومضمّن مع CMA، يعمل بخادم Python قياسي محلي. السيناريو الرئيس يحاكي نمطًا واقعيًا في SaaS متعدد المستأجرين: محلل منخفض الصلاحية في `tenant-red` يستطيع قراءة تصدير `tenant-blue` بسبب غياب فحص ملكية الكائن (BOLA/IDOR)، ويحتوي التصدير على قيمة اعتماد تكامل وهمية. ثم يقبل مسار التقارير تلك القيمة من دون ربط المستأجر المطلوب بملكية الاعتماد، فيعيد تقرير `tenant-blue` لطلب يطلب `tenant-red`.

كل الكيانات والتقارير والاعتمادات مصطنعة. قيمة اعتماد التكامل ليست سرًا حقيقيًا ولا تصلح لأي خدمة. لا تُظهرها في السجلات أو أدلة النتائج أو تقارير CMA؛ استخدم علامة `[REDACTED]`. لا يطبعها الخادم أو الاختبار. الاستجابة الخام لنقطة التصدير تحتوي القيمة الوهمية عمدًا كي تحاكي تسريب اعتماد داخل كائن، ولذلك لا تعرض تلك الاستجابة في مخرجات طرفية أو مرفقات غير منقحة.

## العزل والتحذيرات

- الربط ثابت على `127.0.0.1` فقط؛ لا يوجد خيار `--host` أو ربط بجميع الواجهات.
- لا Docker ولا خدمات أو اعتماديات خارجية ولا اتصالات صادرة. جميع الطلبات إلى عناوين المختبر المحلي فقط.
- لا توجد قاعدة بيانات أو كتابة دائمة إلى القرص. جسم POST محدود بـ 16 KiB، ولا تُسجّل أجسام الطلبات أو الترويسات.
- هوية المحلل ورموز التكامل بيانات تدريب وهمية. لا تستخدم أسرارًا أو بيانات شخصية حقيقية.
- تعرض `/api/exports/export-blue-q4` عمدًا خلل تفويض ملكية متعدد المستأجرين، ويعيد `/api/reports/blue-q4` عمدًا تقريرًا خارج المستأجر الذي يطلبه العميل عند تقديم رمز التكامل التدريبي. هذا نمط ضعيف مقصود محليًا، لا يتصل بأي خدمة خارجية.
- **لا تستخدم المختبر لاختبار أهداف حية أو أطراف ثالثة.** لا تضف مضيفًا أو عنوانًا آخر إلى النطاق. هذا نموذج تعليمي وليس ماسحًا أمنيًا كاملًا ولا دليلًا على ثغرات في أي منتج حقيقي.

## التشغيل والنطاق

لتشغيل الخادم على المنفذ الافتراضي:

```bash
python -m labs.local_web_lab --port 8765
```

يفتح المختبر على `http://127.0.0.1:8765/`، ويطبع قائمة `allowed_urls` الدقيقة عند البدء. لطباعة نطاق المنفذ من دون بدء الخادم:

```bash
python -m labs.local_web_lab --port 8765 --print-scope
```

ولإنشاء القائمة من Python:

```python
from labs.local_web_lab import allowed_urls_for_port

scope = {"allowed_urls": allowed_urls_for_port(8765)}
```

النطاق قائمة عناوين كاملة ومحددة المسار على `127.0.0.1`، لأن CMA يطابق URL دقيقًا على المنفذ غير القياسي. انسخ القائمة المطبوعة كما هي إلى إعداد النطاق المحلي. المنفذ `0` مدعوم للاختبارات فقط؛ بعد ربطه استخدم المنفذ الفعلي الذي يطبعه الخادم.

المسارات تشمل الصفحات المحلية `/` و`/lab/saas` و`/lab/forms` و`/lab/about` و`/lab/redirect`، ونقاط API `/api/exports/export-blue-q4` و`/api/reports/blue-q4` و`/api/type-check`، والملف `/static/lab.js` وفحص الصحة `/healthz`.

## سلسلة الهجوم ومصفوفة ربط النتائج

النتيجة المقصودة من المختبر سلسلة من خطوتين مترابطتين، لا ادعاءان منفصلان بلا سياق. معرّفا `LAB-F1` و`LAB-F2` يطابقان معرّفي الخطوتين اللذين ينشئهما مقيّم المختبر عند بناء المصفوفة.

| المعرّف / الحلقة | المتطلبات المسبقة | دليل مؤكد داخل المختبر (منقّح) | الأثر المحتمل في نمط حقيقي | المعالجة المقترحة | الاعتماد في السلسلة |
|---|---|---|---|---|---|
| **LAB-F1 — BOLA/IDOR في التصدير** | جلسة اختبار محلل `tenant-red` صالحة؛ معرفة معرّف تصدير `tenant-blue` | طلب `GET /api/exports/export-blue-q4` بهوية محلل red أعاد `200` وكائنًا يصرح بملكية `tenant-blue`. الحقل الحساس في دليل النتيجة هو `[REDACTED]`، ولا تُحفظ الاستجابة الخام | قراءة بيانات مستأجر آخر؛ كشف بيانات التصدير واعتماد تكامل وهمي قد يمكّن الوصول إلى خدمة لاحقة | استخرج هوية المستأجر من الجلسة الموثوقة، وافحص صلاحية الوصول إلى كل كائن قبل الإرجاع؛ اختبر فصل المستأجرين على مستوى الخدمة لا الواجهة فقط | يوفّر الكائن المسرب والاعتماد الوهمي اللازمين لـ LAB-F2 |
| **LAB-F2 — اعتماد مكشوف ثم غياب ربط المستأجر في التقارير** | نتيجة LAB-F1؛ الاعتماد التدريبي المستخرج من التصدير؛ طلب التقرير يحدد `tenant-red` | `POST /api/reports/blue-q4` برمز التدريب في `Authorization` وطلب `tenant_id=tenant-red` أعاد `200` وتقريرًا يصرح `tenant-blue`. لم يُدرج الرمز في الأدلة أو الاستجابة | تصعيد من قراءة كائن واحد إلى قراءة تقرير/بيانات مستأجر آخر؛ في نظام حقيقي قد يتسع الأثر بحسب البيانات والصلاحيات المتاحة | قلّل صلاحيات الاعتمادات ودورة حياتها، اربط الرمز بمستأجر وجمهور/موارد محددة، تحقّق من تطابق المستأجر المطلوب مع سياق الاعتماد على الخادم، ودوّر أي اعتماد حقيقي مكشوف | تعتمد على LAB-F1 للحصول على الاعتماد؛ تضاعف أثره بسبب غياب التحقق من ملكية التقرير |

**تفسير السلسلة:** LAB-F1 هو شرط الوصول الأول: يستطيع محلل red قراءة تصدير blue. قيمة التكامل الموجودة في هذا التصدير هي جسر التصعيد التدريبي. LAB-F2 يثبت أن تقديمها مع طلب محدد على red يعيد مع ذلك تقرير blue. يجب أن تبقى الأدلة المترابطة منقحة؛ لا تضع قيمة اعتماد في عنوان URL أو سجل أو مصفوفة نتائج.

## تمارين أدوات CMA

شغّل كل تمرين بنطاق URLs المطبوع للمختبر الجاري فقط. أدوات الجرد والفحص لا ترسل النماذج تلقائيًا، ولا حاجة إلى إجراء أي طلب خارج `127.0.0.1`.

### 1. الجرد المحدود (`crawl_site`)

ابدأ من `/` مع قائمة `allowed_urls` الدقيقة وحد أقصى خمس صفحات. تحقق من اكتشاف `/lab/saas` و`/lab/forms` و`/lab/about`. يجب أن تبقى جميع العناوين ضمن المضيف والمنفذ المحليين. افحص `/lab/redirect` منفردًا: المتوقع رصد `302` إلى مسار محلي دون متابعة التحويل.

### 2. فحص بيانات الصفحة (`inspect_page`)

افحص `/lab/forms` أو `/lab/saas`. المتوقع ظهور أسماء المسارات وبيانات النموذج فقط، دون قيم الحقول أو أجسام الاستجابة. يعمل Chromium على لقطة محلية مع تعطيل JavaScript وطلبات الموارد، ولا يرسل النموذج. يُتخطى اختبار المتصفح وحده إذا لم يتوفر Playwright وChromium.

### 3. المقارنة التفاضلية (`mutate_and_fuzz_request`)

على `/api/type-check` محليًا، قارن JSON `{"age":37}` بالتبديل النوعي. المتوقع `200` للأساس و`400` للقيمة المعدلة. تُرجع الأداة حالة وبصمات فقط، لا جسم الاستجابة. استخدمها على هذا المسار المحلي فقط.

### 4. فحص JavaScript (`analyze_javascript_source`)

اجلب `/static/lab.js` محليًا ثم حلّل النص. المتوقع اكتشاف مسارات API الوهمية والإشارة إلى تعيين مفتاح تدريبي. يجب أن يكون `value_redacted` صحيحًا ولا تظهر القيمة في نتيجة المحلل. هذا تحليل نصي محلي بلا طلبات شبكة.

### 5. إثبات السلسلة يدويًا أو عبر المقيّم المحلي

الاختبار `test_chain_confirms_cross_tenant_export_and_report_access_without_token_in_evidence` ينفّذ الخطوتين عبر HTTP على loopback فقط: يثبت أن طلبًا بلا جلسة يواجه `401`، وأن محلل red الموثق يقرأ تصدير blue، ثم يقدّم الاعتماد المستخرج في الذاكرة لطلب report يحدد red ويستلم تقرير blue. لا يطبع الاختبار جسم التصدير أو قيمة الاعتماد، ويُنشئ كائن دليل منقحًا. مقيّم السلسلة ينفّذ خمسة طلبات محلية محدودة (بما فيها ضوابط سلبية)، ويرفض أي مضيف غير `127.0.0.1` قبل الاتصال، ثم يربط LAB-F1 وLAB-F2 بمصفوفة منقحة:

```bash
python -m labs.local_web_lab.evaluation --base-url http://127.0.0.1:8765
```

يشترط تشغيل الخادم أولًا في طرفية أخرى. لا تتبع أي تحويلات، ولا تُطبع قيمة الرمز الوهمي في نتيجة المقيّم.

## حدود التمرين

النتائج تؤكد السلوك المحدد الذي برمجه هذا النموذج المحلي فقط. لا تمثل اكتشافًا عامًا لثغرات، ولا تحليلًا لكود منتج فعلي، ولا تحققًا من أنظمة هوية أو صلاحيات حقيقية. أدوات CMA هنا محدودة بعدد صفحات وطلبات وأحجام استجابة، لا تتبع التحويلات، لا تنفذ JavaScript في الفحص، ولا ترسل النماذج تلقائيًا. لا تعتبر النتائج مسحًا شاملًا.

## الاختبارات والتنظيف

من جذر المشروع:

```bash
python -m unittest discover -s tests -p 'test_local_lab.py' -v
python -m unittest tests.test_local_lab_evaluation tests.test_chain_engine -v
```

تبدأ الاختبارات الخادم على `127.0.0.1` بمنفذ مؤقت، وتوقفه وتغلق المقبس والخيط بعد كل اختبار. اختبار المتصفح وحده يُتخطى عند غياب Playwright أو Chromium. أوقف التشغيل اليدوي بـ `Ctrl-C`. لا توجد حالة دائمة تحتاج إلى تنظيف.

## استكشاف الأخطاء

- **المنفذ مشغول:** اختر رقمًا آخر، مثل `8766`، وأعد طباعة النطاق للمنفذ نفسه.
- **رفض النطاق:** استخدم العناوين الكاملة المطبوعة للمضيف والمنفذ الجاريين؛ لا تستبدل `127.0.0.1` بعنوان الشبكة أو `localhost`.
- **`401` من التصدير:** المسار يتطلب جلسة التدريب الوهمية لمحلل red. لا تستخدم حسابًا أو اعتمادًا حقيقيًا.
- **`401` من التقارير:** نقطة التقارير تقبل اعتماد التكامل التدريبي الموجود في التصدير فقط؛ لا تعرضه أو تسجله أثناء التمرين.
- **`400` أو `413`:** تأكد من JSON صالح ونوع محتوى `application/json`؛ الحد الأقصى للجسم 16 KiB. `/api/type-check` يرفض النص و`null` عمدًا.
- **اختبار المتصفح متخطى:** Playwright أو Chromium غير متاح. بقية الخادم والاختبارات مستقلة عنه.
